## 3. What is failing — and the root causes
### 3.1 "Fails to reply properly" — latency/timeout architecture (P0)
A single text turn can serially call: Qwen-122B extraction, Nemotron
question-plan review, Nemotron question verification, Llama-70B phrasing,
GLM-5 safety, MiniMax compression — plus Nyckel/Roboflow/vision on image
turns. On Vercel **no route exports `maxDuration` and vercel.json has no
function config**, so the function runs under the platform default (10–15s)
while internal budgets assume more (client timeout 30s
(`request-timeout.ts`), MiniMax 45s). When the stack of upstream calls
exceeds the platform cap, the function is killed mid-turn → the user sees a
dead/garbled reply. VET-1570C bounding phrasing latency treated one symptom;
the per-turn call count is the disease.
### 3.2 "Asks wrong questions" — language understanding by regex (P0/P1)
WHICH question is asked is decided deterministically from `known_symptoms` ×
clinical matrix. So wrong questions = wrong/missed symptom extraction.
Extraction is keyword regex + a single Qwen JSON call, then ~3,000 lines of
deterministic coercion (`answer-coercion.ts` 633, `answer-extraction.ts` 893,
`extraction-helpers.ts` 668, plus pending-question recovery). Every new owner
phrasing ("he's been off lately", smart quotes, "not really") is a new bug —
VET-707B (curly apostrophe regex), VET-709 (phrasing families), VET-1380s are
all the same failure class. Deterministic *clinical logic* is right;
deterministic *natural-language parsing* is a failure factory. There is no
owner-language eval set, so each fix is anecdote-driven and regressions are
invisible until a tester hits them.
### 3.3 Production split-brain — Supabase (P0, open)
**VET-1569C (issue #582): prod REST/Auth and DATABASE_URL point at different
Supabase projects.** Auth sessions live in one project, data in another →
`session_expired` bounces, writes that don't show up, reports that vanish.
Eight `.env.prod*` variants sit in the repo root — env drift made this
inevitable. This alone can make the whole app feel broken to a signed-in user.
### 3.4 Hero feature 90 days stalled — one unexecuted operator step (P0)
Quest 1 (VET-910 benchmark live baseline) requires a provisioned pod and one
command. Everything downstream (silent trials, narrow-model promotion,
multimodal pilot) is gated on a baseline that has never been recorded. The
promotion rule can never fire, so by construction the hero feature cannot
ship. Either run the bring-up under a budget cap, or re-host the benchmark on
already-deployed sidecars/NIM and unblock the loop without RunPod.
### 3.5 Verifier gap — tests don't measure the user experience
3,116 tests pass while users experience failure: the suite verifies
deterministic logic, not live latency, live extraction quality, or
conversation feel. The benchmark harness that WOULD measure this has never
run live. Classic Goodhart setup: green gates, red product.
### 3.6 Hygiene and process drag
- ~100 `pawvital-ai-*` worktree clones in `G:\MY Website` — disk, confusion,
stale-branch hazards (vault itself warns about it).
- Marketing redesign (~20 files) uncommitted in the implementation worktree
for a week+, blocking clean landings.
- June 3: seven identical retry commits fighting the AI review gate — gate
friction burning hours.
- Four mandatory frameworks (thermo/SIA/AutoLab/AutoScientists) on every
ticket pushes effort into ceremony on small fixes.
## 4. Frontend assessment
Component architecture is healthy (VET-802 extraction; symptom-checker
components are small and focused; report library reused on /history). Pains:
no streaming/progress feedback during long turns (Web PubSub live updates
exist but the UI feel is still request/response), robotic fallback phrasing
